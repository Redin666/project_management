# Фаза 1 — Выбор концепции проекта


## Цель

Выбрать концепцию компактного программного проекта, которая будет использоваться в следующих фазах.

## Что нужно сделать

- придумать не менее 4 концепций;
- сформулировать не менее 4 критериев оценки;
- каждому участнику оценить важность критериев и альтернативы;
- упорядочить три оценки как пессимистичную, ожидаемую и оптимистичную;
- выполнить нечёткий коллективный TOPSIS;
- выполнить чёткий коллективный МАИ;
- сравнить результаты и сформулировать вывод.

## Результаты фазы

Здесь будут храниться:
- описания концепций;
- [критерии оценки (benefit и cost)](criteria/README.md);
- [экспертные оценки](expert-assessment/README.md);
- [расчёты TOPSIS](topsis/README.md);
- расчёты МАИ;
- итоговое сравнение и выбранная концепция.

## Задачи

Конкретные работы ведутся через GitHub Issues. Для каждой задачи фиксируются исполнитель, период работы, плановые и фактические трудозатраты.


## Концепции проекта

Утверждённый набор альтернатив вынесен в отдельный файл: [concepts/README.md](concepts/README.md).

## Критерии оценивания

Для всех четырёх концепций используется единый набор из **7 критериев**: **4 критерия преимуществ (benefit)**, для которых большее значение предпочтительнее, и **3 критерия затрат и ограничений (cost)**, для которых меньшее значение предпочтительнее.

- [Описания критериев, шкала 0–10 и направления оптимизации](criteria/README.md)
- [Шаблон индивидуальных экспертных оценок](criteria/assessment-template.md)

Критерии подготовлены для проверки командой в рамках [issue #4](https://github.com/Redin666/project_management/issues/4). Экспертные оценки, веса и расчёты выполняются отдельно.
