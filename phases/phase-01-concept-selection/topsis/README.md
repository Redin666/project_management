# Нечёткий коллективный TOPSIS

## Цель

Сравнить четыре концепции проекта на основе семи критериев и коллективных экспертных оценок.

Методика построена по тому же общему принципу, который использован в примерах других команд: три индивидуальные оценки формируют треугольное нечёткое число, затем выполняются нормализация, взвешивание, поиск идеального и антиидеального решений, расчёт расстояний и коэффициента близости.

При этом все концепции, критерии и исходные оценки в этом репозитории собственные.

## Этап 1 — Формирование нечётких оценок

Для каждого показателя:

`(l, m, u) = (MIN(x1,x2,x3), MEDIAN(x1,x2,x3), MAX(x1,x2,x3))`.

Нечёткий вес критерия получается делением трёх компонентов оценки важности на 10.

## Этап 2 — Нормализация

Для benefit-критериев K1–K4:

`r = (l/U, m/U, u/U)`, где `U` — максимальная верхняя граница по критерию.

Для cost-критериев K5–K7:

`r = (L/u, L/m, L/l)`, где `L` — минимальная нижняя граница по критерию.

После такого преобразования большее значение всегда означает более предпочтительный результат.

## Этап 3 — Взвешивание

Нормализованные тройки покомпонентно умножаются на нечёткие веса критериев.

## Этап 4 — Идеал и антиидеал

По каждому критерию:

- идеал — максимальная верхняя компонента взвешенной оценки;
- антиидеал — минимальная нижняя компонента.

## Этап 5 — Расстояния

Для треугольных чисел используется расстояние:

`d(x,y) = sqrt(((xl-yl)^2 + (xm-ym)^2 + (xu-yu)^2) / 3)`.

Далее для каждой альтернативы суммируются расстояния по семи критериям:

- `D+` — расстояние до идеала;
- `D−` — расстояние до антиидеала.

Коэффициент близости:

`CC = D− / (D+ + D−)`.

Чем больше CC, тем предпочтительнее концепция.

## Результат расчёта

| Место | Альтернатива | D+ | D− | CC |
|---:|---|---:|---:|---:|
| **1** | **A1 — Система управления результатами тестирования на проникновение** | 1.4837 | 1.8118 | **0.5498** |
| 2 | A4 — Система управления проверками защищённости информационных систем | 1.6720 | 1.7190 | 0.5069 |
| 3 | A3 — Система регистрации и обработки инцидентов информационной безопасности | 1.8326 | 1.3849 | 0.4304 |
| 4 | A2 — Система контроля безопасности процесса разработки ПО | 2.0436 | 1.2064 | 0.3712 |

## Интерпретация

**A1** занимает первое место за счёт сильного сочетания практической значимости, демонстрационной ценности и умеренных затрат на MVP и сопровождение.

**A4** находится близко ко второму месту благодаря низкой трудоёмкости и небольшим внешним зависимостям, но уступает A1 по функциональной, интеграционной и исследовательской ценности.

**A3** имеет очень высокую практическую значимость, однако проигрывает по затратам на реализацию и эксплуатацию.

**A2** наиболее силён по потенциалу интеграции и развития, но в данном наборе оценок получает самые высокие затраты и зависимости, что снижает итоговый CC.

## Вывод

По текущему расчётному набору экспертных оценок лидирует **A1 — «Система управления результатами тестирования на проникновение»**, `CC = 0.5498`.

Разрыв между A1 и A4 небольшой, поэтому перед фиксацией окончательного результата требуется подтверждение трёх индивидуальных колонок экспертами. После подтверждения Excel-книга автоматически пересчитает все этапы.
