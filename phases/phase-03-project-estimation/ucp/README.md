# P3-03 — Оценка проекта методом Use Case Points (UCP)

## Цель и исходные данные

Оценить размер MVP системы управления результатами тестирования на проникновение методом **Use Case Points**. База — [12 Use Cases из P3-01](../use-cases/README.md), с [описанием сценариев](../use-cases/details.md). Вне MVP остаются автоматическое сканирование, выполнение атак, SIEM/SOAR, биллинг и договоры. Оценка P3-03 относится к **реализации системы**, а не к учебному времени выполнения задания P3-03 из Фазы 2.

**Статус:** расчёт выполнен; оценки числа транзакций, технических факторов и факторов окружения — **предварительные экспертные допущения**, не согласованные командой. При уточнении требований и состава разработчиков они должны быть пересмотрены.

## Методика

По классическому методу Карнера:

- **UAW** — сумма весов уникальных акторов: простой интерфейс/API — 1, протокол взаимодействия — 2, человек через GUI — 3.
- **UUCW** — сумма весов Use Cases: 1–3 транзакции — 5, 4–7 — 10, 8 и более — 15.
- **UUCP = UAW + UUCW**.
- **TCF = 0,6 + 0,01 × TFactor**, где TFactor — сумма 13 взвешенных технических факторов.
- **ECF = 1,4 − 0,03 × EFactor**, где EFactor — сумма 8 взвешенных факторов окружения.
- **UCP = UUCP × TCF × ECF**.
- **Трудоёмкость = UCP × коэффициент производительности (ч/UCP)**.

Для T1–T13 и E1–E8 применяется экспертная шкала 0–5. Методические сведения: [исследование по UCP (PMC)](https://pmc.ncbi.nlm.nih.gov/articles/PMC4638361/) и [правила подсчёта (Andа и др.)](https://people.eecs.ku.edu/~saiedian/811/Papers/Use-Case-Points/use-case-points-anda.pdf).

## 1. Акторы и UAW

Актор считается **один раз**, даже если участвует в нескольких Use Cases. В P3-01 перечислены четыре пользовательские роли; все они взаимодействуют с системой через пользовательский интерфейс. Других самостоятельных внешних систем/акторов в MVP не описано.

| Актор | Класс | Вес |
|---|---|---:|
| Руководитель проекта / тимлид | Сложный | 3 |
| Пентестер | Сложный | 3 |
| Представитель заказчика | Сложный | 3 |
| Администратор | Сложный | 3 |
| **Итого UAW** | | **12** |

## 2. Use Cases и UUCW

Транзакции — укрупнённые завершённые действия по сценарию, а **не количество полей, таблиц БД или CFP**. Описания P3-01 достаточно краткие, поэтому приведённое разбиение является оценочным; в спорных местах учитываются валидация, создание/изменение результата и его отображение. При детализации пользовательских потоков количество транзакций и классы могут измениться.

| Use Case | Транзакций | Класс | Вес | Основание для подсчёта |
|---|---:|---|---:|---|
| UC-01 | 4 | Средний | 10 | Ввод параметров; проверка; создание; отображение карточки |
| UC-02 | 4 | Средний | 10 | Добавление актива; проверка; сохранение; обновление scope |
| UC-03 | 4 | Средний | 10 | Ввод находки; валидация/scope; сохранение; присвоение ID |
| UC-04 | 4 | Средний | 10 | Открытие; изменение; контроль версии; сохранение |
| UC-05 | 3 | Простой | 5 | Прикрепление файла; проверка; сохранение связи с находкой |
| UC-06 | 3 | Простой | 5 | Выбор находки; проверка пользователя; назначение |
| UC-07 | 3 | Простой | 5 | Задание критериев; поиск; вывод результата |
| UC-08 | 5 | Средний | 10 | Выбор параметров; чтение данных; формирование; сохранение версии; отображение |
| UC-09 | 3 | Простой | 5 | Выбор формата; получение версии; выдача файла |
| UC-10 | 3 | Простой | 5 | Ввод комментария; проверка/сохранение; отображение |
| UC-11 | 5 | Средний | 10 | Открытие находки; проверка; фиксация результата; доказательство; обновление статуса |
| UC-12 | 4 | Средний | 10 | Выбор записи; редактирование; проверка ограничений; сохранение |

**UUCW = 5 × 5 + 7 × 10 + 0 × 15 = 95.**

**UUCP = UAW + UUCW = 12 + 95 = 107.**

## 3. Техническая сложность (TCF)

Фиксированные веса — по методике UCP, значения 0–5 — выбранные для данного MVP предварительные экспертные оценки.

| Фактор | Содержание | Вес | Оценка | Произведение | Обоснование |
|---|---|---:|---:|---:|---|
| T1 | Распределённая система | 2 | 1 | 2 | Единое веб-приложение без распределённой архитектуры |
| T2 | Производительность | 1 | 2 | 2 | Умеренные требования к поиску и отчётам |
| T3 | Эффективность конечных пользователей | 1 | 3 | 3 | Частые рабочие операции и фильтрация |
| T4 | Сложная обработка | 1 | 3 | 3 | Агрегация отчётов и состояние повторных проверок |
| T5 | Повторное использование кода | 1 | 2 | 2 | Возможно переиспользование форм и проверок доступа |
| T6 | Простота установки | 0.5 | 2 | 1 | Предполагается обычное развёртывание веб-системы |
| T7 | Простота использования | 0.5 | 4 | 2 | Несколько ролей и интенсивное использование форм |
| T8 | Переносимость | 2 | 2 | 4 | Веб-приложение без специальных требований к ОС |
| T9 | Лёгкость модификации | 1 | 3 | 3 | Изменяемые статусы и структура данных |
| T10 | Параллельная работа | 1 | 3 | 3 | Одновременная работа участников проекта |
| T11 | Специальные требования безопасности | 1 | 5 | 5 | Уязвимости, доказательства и ролевая модель доступа |
| T12 | Доступ сторонних систем | 1 | 1 | 1 | API и интеграции не включены в MVP |
| T13 | Специальное обучение пользователей | 1 | 1 | 1 | Обычные интерфейсы для специалистов |
| **Итого** | | | | **32** | |

**TCF = 0,6 + 0,01 × 32 = 0,92.**

## 4. Факторы окружения (ECF)

Эти значения особенно зависят от фактического состава и опыта команды; без интервью с командой они **не являются измеренными характеристиками**.

| Фактор | Содержание | Вес | Оценка | Произведение | Обоснование |
|---|---|---:|---:|---:|---|
| E1 | Знакомство с процессом разработки | 1.5 | 2 | 3 | Предварительное предположение о знакомстве команды с процессом |
| E2 | Опыт работы с данным типом приложений | 0.5 | 2 | 1 | Предполагается ограниченный опыт с системами пентест-отчётности |
| E3 | Опыт объектно-ориентированной разработки | 1 | 3 | 3 | Условно средний уровень, требует подтверждения |
| E4 | Квалификация ведущего аналитика | 0.5 | 3 | 1.5 | Условно средний уровень, требует подтверждения |
| E5 | Мотивация | 1 | 4 | 4 | Учебная команда, задачи и ответственные определены |
| E6 | Стабильность требований | 2 | 3 | 6 | Границы MVP обозначены, детали ещё подлежат уточнению |
| E7 | Частичная занятость | -1 | 4 | -4 | Работа над учебным проектом предполагается неполной |
| E8 | Сложность языка реализации | -1 | 2 | -2 | Стек не зафиксирован, взята умеренная оценка |
| **Итого** | | | | **12,5** | |

**ECF = 1,4 − 0,03 × 12,5 = 1,025.**

В частности, E7 отражает предполагаемую неполную занятость, а E8 — неопределённость языка программирования. Оба пункта следует подтвердить на следующем этапе.

## 5. Итоговый UCP и трудоёмкость

| Показатель | Значение |
|---|---:|
| UAW | **12** |
| UUCW | **95** |
| UUCP | **107** |
| TFactor | **32** |
| TCF | **0,92** |
| EFactor | **12,5** |
| ECF | **1,025** |
| **UCP** | **100,901** |
| Принятое базовое значение производительности | **20 ч/UCP** |
| **Ориентировочная трудоёмкость реализации** | **2018,02 чел.-ч** |

Формулы:

```text
UCP = (12 + 95) × 0.92 × 1.025 = 100.901
Effort = 100.901 × 20 = 2018.02 person-hours
```

Для оценки чувствительности к **неподтверждённому** коэффициенту производительности:

| Коэффициент | Трудоёмкость |
|---|---:|
| 15 ч/UCP | 1513,52 чел.-ч |
| **20 ч/UCP (базовый)** | **2018,02 чел.-ч** |
| 25 ч/UCP | 2522,53 чел.-ч |

Диапазон **не является статистическим доверительным интервалом**. 20 ч/UCP — иллюстративная типовая исходная ставка без калибровки на исторических проектах данной команды. UCP может переоценивать небольшой CRUD-ориентированный MVP, поэтому результат нельзя считать гарантией срока или бюджета.

[Коллективная экспертная оценка P3-04](../expert-estimation/README.md) составляет **68 чел.-ч**. Эти значения существенно расходятся: ставка UCP рассчитана для полного цикла реализации при условных параметрах, а экспертную оценку ещё нужно проверить на полноту охвата. Согласование границ оценки и сравнение методов выполняются в **P3-06**, а не подбором ставки UCP под готовые 68 ч.
