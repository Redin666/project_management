# COSMIC Function Points — оценка проекта

## Цель

Оценить функциональный размер системы управления результатами тестирования на проникновение методом COSMIC на основе Use Cases P3-01.

## Методическая основа

В COSMIC функциональный процесс представляется движениями данных четырёх типов:

- **Entry (E)** — данные входят в измеряемое ПО от функционального пользователя;
- **Exit (X)** — данные выходят из ПО к функциональному пользователю;
- **Read (R)** — данные читаются из постоянного хранилища;
- **Write (W)** — данные записываются в постоянное хранилище.

Каждое идентифицированное движение данных имеет размер **1 CFP**. Размер функционального процесса равен сумме его E + X + R + W, а размер системы — сумме процессов.

Методическая ссылка: https://cosmic-sizing.org/cosmic-sizing/intro/measurement-process/

## Граница измерения

Измеряется прикладная система управления результатами пентеста. Пользователи системы находятся за функциональной границей; база данных и файловое хранилище рассматриваются как persistent storage внутри измеряемой системы.

## Интерпретация

Функциональный размер выбранного MVP составляет **53 CFP**.

Наибольший вклад в размер дают:

- **UC-08 Формирование отчёта — 7 CFP**, потому что процесс использует данные проекта, scope, находок и доказательств и сохраняет сформированную версию;
- **UC-11 Re-test — 6 CFP**, потому что процесс читает существующую находку и связанные доказательства, сохраняет отдельный результат повторной проверки и обновляет статус находки;
- **UC-03 Регистрация уязвимости** и **UC-06 Назначение ответственного — по 5 CFP**.

COSMIC здесь оценивает именно функциональный размер, а не человеко-часы. Сопоставление с трудозатратами выполняется далее через UCP и коллективную экспертную оценку.
