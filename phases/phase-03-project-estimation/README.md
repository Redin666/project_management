## Порядок выполнения

1. **P3-01** формирует основу всей дальнейшей оценки.
2. После P3-01 параллельно можно выполнять **P3-02, P3-03 и P3-04**.
3. После P3-04 выполняется **P3-05**.
4. После P3-02, P3-03 и P3-05 выполняется **P3-06**.
5. После сравнительного анализа выполняется **P3-07**.
6. Завершает фазу **P3-08**.

## Что должно быть получено

### P3-01 — Use Cases

Не менее **10 Use Cases** для выбранной системы. Нужно учитывать:

- основных акторов;
- основной сценарий;
- альтернативные сценарии;
- негативные/ошибочные сценарии;
- границы MVP.

### P3-02 — COSMIC Function Points

Необходимо определить функциональные процессы и движения данных:

- Entry;
- Exit;
- Read;
- Write.

После этого рассчитывается итоговый размер проекта в CFP.

### P3-03 — Use Case Points

Необходимо получить:

- UAW;
- UUCW;
- TCF;
- ECF;
- итоговый UCP;
- ориентировочную оценку трудозатрат.

### P3-04 и P3-05 — коллективная экспертная оценка

Команда выбирает допустимый экспертный метод: planning poker, Delphi либо согласованное открытое обсуждение.

Оцениваются трудозатраты Use Cases или более мелких элементов, затем оценки агрегируются в оценку всего проекта.

### P3-06 — сравнение методов

COSMIC, UCP и коллективная экспертная оценка сводятся в единый сравнительный анализ с объяснением расхождений.

### P3-07 — команда и срок

На основе полученного масштаба проекта необходимо определить:

- ориентировочный размер команды;
- необходимые роли;
- специальные компетенции;
- ориентировочный срок реализации.

### P3-08 — сокращение функциональности

Определить функции, которые:

- не являются критичными для MVP;
- при этом существенно увеличивают размер или трудоёмкость проекта.

Финальный результат должен содержать аргументированный список кандидатов на исключение.

## Результаты Фазы 3

По завершении в репозитории должны находиться:

- перечень 10–15 Use Cases;
- COSMIC-оценка;
- UCP-оценка и трудозатраты;
- коллективная экспертная оценка;
- итоговая агрегированная оценка;
- сравнительный анализ;
- оценка команды и срока;
- предложения по сокращению функциональности;
- итоговый вывод по масштабу проекта.
