# Фаза 2 — Распределение работы

## Статус

🟡 Организационный этап запущен.

## Цель

Распределить работы **Фазы 3 — Оценка проекта** между участниками команды на основе:

- экспертной оценки трудоёмкости задач;
- индивидуальных предпочтений участников;
- формальной оптимизационной модели.

## Связь с Фазой 3

Фазы 2 и 3 выполняются последовательно:

1. сначала в Фазе 2 формируется полный перечень задач Фазы 3;
2. команда оценивает их трудоёмкость;
3. каждый участник независимо оценивает предпочтительность задач;
4. формулируется задача оптимального распределения;
5. решается оптимизационная модель;
6. только после этого исполнители задач Фазы 3 фиксируются в GitHub Issues и RACI;
7. команда переходит к выполнению Фазы 3.

**Важно:** заранее вручную закреплять исполнителей Фазы 3 не следует, иначе теряется смысл оптимизационного распределения.

## Декомпозиция Фазы 3

Подготовленный перечень работ: [phase-03-task-decomposition.md](phase-03-task-decomposition.md).

Выделено 8 рабочих пакетов:

- P3-01 — Use Cases и границы проекта;
- P3-02 — COSMIC Function Points;
- P3-03 — Use Case Points и оценка трудозатрат;
- P3-04 — коллективная экспертная оценка элементов проекта;
- P3-05 — агрегирование экспертных оценок;
- P3-06 — сравнение COSMIC, UCP и экспертной оценки;
- P3-07 — оценка команды, компетенций и срока;
- P3-08 — анализ сокращения функциональности и итоговые выводы.

## Экспертная оценка трудоёмкости

Шаблон: [effort-estimation-template.md](effort-estimation-template.md).

Предлагаемый порядок:

1. каждый участник независимо оценивает чистое время выполнения каждой задачи;
2. оценки сравниваются;
3. сильные расхождения обсуждаются;
4. команда фиксирует согласованную итоговую оценку трудоёмкости.

Фактические значения должны быть получены от участников команды, а не сгенерированы автоматически.

## Индивидуальные предпочтения

Шаблоны находятся в каталоге [preferences](preferences/README.md).

Каждый участник независимо оценивает интерес к каждой задаче по шкале **1–5**:

- 1 — выполнять крайне нежелательно;
- 2 — низкая предпочтительность;
- 3 — нейтрально;
- 4 — предпочтительно;
- 5 — очень желательно.

## Оптимизационная модель

Черновая постановка модели подготовлена в [optimization-model.md](optimization-model.md).

После заполнения трудоёмкости и предпочтений необходимо:

- зафиксировать окончательную целевую функцию;
- определить ограничения;
- выбрать инструмент решения;
- сохранить исходные данные и результат;
- по результату назначить исполнителей Issues Фазы 3.

## Результаты Фазы 2

По завершении должны быть получены:

- согласованная декомпозиция Фазы 3;
- оценки трудоёмкости;
- три индивидуальные матрицы предпочтений;
- математическая постановка задачи;
- решение оптимизационной модели;
- итоговое распределение задач Фазы 3;
