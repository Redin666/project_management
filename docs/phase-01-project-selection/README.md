# Фаза 1 — выбор концепции проекта

## Цель

Выбрать наиболее подходящую концепцию небольшого программного проекта с помощью двух методов коллективного многокритериального выбора:
- нечёткий коллективный TOPSIS;
- чёткий коллективный МАИ.

## Требуемые результаты

- не менее 4 концепций проекта;
- не менее 4 критериев оценки;
- трёхточечные оценки каждого из 3 участников;
- расчёт TOPSIS;
- расчёт МАИ;
- сравнение результатов;
- обоснованный выбор итоговой концепции.

## Первичные кандидаты

1. **Vulnerability Tracker** — учёт обнаруженных уязвимостей, критичности, статуса и ответственных.
2. **IT Asset Manager** — учёт устройств, программного обеспечения и ответственных лиц.
3. **Study Task Manager** — учёт учебных заданий, сроков, предметов и статусов.
4. **Security Checklist Manager** — создание и прохождение чек-листов проверок информационной безопасности.

Это только стартовый набор. Команда может заменить концепции до начала экспертного оценивания.

## Возможные критерии

- сложность реализации MVP;
- полезность и практическая ценность;
- удобство декомпозиции на 10–15 Use Cases;
- трудоёмкость подготовки UML;
- возможность продемонстрировать результат;
- интерес команды к теме.

Итоговый набор критериев должен быть согласован всей командой.
