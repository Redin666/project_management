## 1️⃣ Фаза 1 — Выбор концепции проекта

### Суть фазы

На первом этапе команда должна выбрать концепцию небольшого программного проекта, с которой будет работать дальше на протяжении остальных фаз.

Для этого необходимо:

- придумать не менее **4 концепций программного проекта**;
- сформулировать не менее **4 критериев оценки**;
- каждому участнику дать экспертные оценки важности критериев и альтернатив;
- упорядочить три оценки как **пессимистичную, ожидаемую и оптимистичную**;
- определить лучший вариант методом **нечёткого коллективного TOPSIS**;
- определить лучший вариант методом **чёткого коллективного МАИ**;
- сравнить полученные результаты и сформулировать итоговый вывод.

➡️ [Материалы Фазы 1](phases/phase-01-concept-selection/README.md)

**Результат Фазы 1:** выбрана концепция **A1 — «Система управления результатами тестирования на проникновение»**. Она используется как основа Фаз 2–5.

## 2️⃣ Фаза 2 — Распределение работы

### Суть фазы

На втором этапе команда должна распределить между участниками работы следующей фазы на основе **трудоёмкости задач** и **индивидуальных предпочтений**.

Для этого необходимо:

- сначала разбить работу **Фазы 3** на отдельные задачи;
- оценить сложность или трудозатраты задач **экспертным путём**;
- каждому участнику дать **индивидуальные оценки предпочтительности** задач;
- сформулировать и обосновать задачу распределения на основе трудоёмкости и предпочтений:
  - определить переменные решения;
  - задать целевую функцию;
  - определить ограничения;
  - задать правила балансировки нагрузки;
- решить задачу распределения с использованием подходящего инструмента, например **Pyomo, OpenSolver, NEOS** или другого оптимизационного средства;
- зафиксировать итоговое распределение работ Фазы 3 между участниками.

➡️ [Материалы Фазы 2](phases/phase-02-work-distribution/README.md)

**Результат Фазы 2:** выполнены декомпозиция Фазы 3, экспертная оценка трудоёмкости и индивидуальные предпочтения; сформулирована MILP-задача распределения и решена в **Pyomo + HiGHS**. Оптимальное распределение подтвердило текущих исполнителей, поэтому переназначение задач не потребовалось.

## 3️⃣ Фаза 3 — Оценка проекта

### Суть фазы

На третьем этапе команда должна оценить масштаб выбранного проекта несколькими независимыми способами и на основе результатов определить примерную трудоёмкость, состав команды, срок реализации и возможное сокращение функциональности.

Для этого необходимо:

- подготовить не менее **10 Use Cases** выбранного проекта;
- для Use Cases учитывать не только основной, но также **альтернативные и негативные сценарии**;
- оценить функциональный размер проекта методом **COSMIC Function Points**;
- оценить проект методом **Use Case Points (UCP)** и получить ориентировочную трудоёмкость;
- коллективно оценить трудоёмкость Use Cases, User Stories или более мелких элементов проекта экспертным методом;
- добиться согласованной коллективной оценки и агрегировать её в оценку всего проекта;
- сопоставить результаты **COSMIC, UCP и экспертной оценки**;
- определить:
  - примерный размер команды;
  - необходимые роли и специальные компетенции;
  - ориентировочный срок реализации;
- определить менее важные, но ресурсоёмкие функции, которые можно исключить или перенести за пределы MVP;
- сформулировать итоговый вывод о масштабе проекта.

➡️ [Материалы Фазы 3](phases/phase-03-project-estimation/README.md)

**Текущий результат Фазы 3:** подготовлено **12 Use Cases**, выполнена оценка **53 CFP по COSMIC** и **100,901 UCP** (ориентировочно **2018 чел.-ч** при 20 ч/UCP), коллективная экспертная оценка составляет **68 чел.-ч**. Сравнение методов (P3-06) показало, что они согласны в структуре (наиболее трудоёмкие — отчёт, re-test, регистрация уязвимости), но расходятся в абсолютной трудоёмкости почти в **30 раз**: экспертная оценка покрывает только реализацию функционального ядра, UCP — полный цикл. Базой для оценки команды и срока принята UCP-оценка **2018 чел.-ч** (диапазон 1514–2825). По P3-07 полный MVP требует **4 FTE** и около **21 недели**. По P3-08 рекомендовано исключить из MVP повторную проверку, комментарии заказчика и отдельный экспорт отчёта (UC-09/10/11): объём снижается до **40 CFP / ~1584 чел.-ч**, срок при 4 FTE — до **~16 недель**. Фаза 3 завершена.

## 4️⃣ Фаза 4 — Прогнозирование

### Суть фазы

Фаза 4 является метаэтапом для Фазы 5: сначала команда должна определить, какие именно работы предстоит выполнить в Фазе 5, а затем спрогнозировать срок их выполнения на основе собственной предыдущей статистики.

Необходимо:

- разбить работу **Фазы 5** на отдельные задачи;
- для каждой задачи дать **трёхточечную оценку времени**: оптимистичную, наиболее вероятную и пессимистичную;
- собрать историю количества задач, завершённых командой по неделям;
- рассматривать недельный throughput как эмпирическое дискретное распределение;
- выполнить первую Монте-Карло модель, где на каждой неделе сэмплируется количество завершённых задач;
- определить срок Фазы 5 с **80% достоверностью**;
- собрать историю суммарных человеко-часов, которые команда фактически могла выделять предмету по неделям;
- выполнить вторую Монте-Карло модель:
  - длительность каждой задачи сэмплируется из треугольного распределения по трёхточечной оценке;
  - недельная доступная мощность сэмплируется из исторического распределения человеко-часов;
- также определить срок с **80% достоверностью**;
- сравнить результаты двух моделей и объяснить причины расхождения.

➡️ [Материалы Фазы 4](phases/phase-04-forecasting/README.md)

**Текущий расчёт:** модель throughput даёт **P80 = 5 недель**, модель по человеко-часам и треугольным длительностям — **P80 = 13 недель**.

## 5️⃣ Фаза 5 — Планирование

### Суть фазы

На пятом этапе строится детальный ресурсный и календарный план реализации проекта, выбранного в Фазе 1 и оценённого в Фазе 3.

Необходимо:

- разложить реализацию проекта примерно на **20–25 работ**;
- на основе Фазы 3 определить состав команды по специальностям;
- рассматривать специальности как типы доступных ресурсов;
- для каждой работы задать, сколько специалистов каждого типа требуется;
- определить непосредственные связи предшествования между работами;
- решить задачу календарно-ресурсного планирования несколькими эвристиками:
  - SLK;
  - FREE;
  - LST;
  - LFT;
  - LSTLFT;
  - GRPW;
  - LPT;
  - MIS;
  - GRD;
  - GRWC;
  - GCRWC;
  - ROT;
- дополнить набор случайно сгенерированными порядками приоритета;
- сравнить найденные расписания и выбрать лучшее;
- перенести выбранное решение на обычный график **8 часов в день / 40 часов в неделю**;
- определить плановые сроки отдельных работ, этапов и всего проекта.

➡️ [Материалы Фазы 5](phases/phase-05-planning/README.md)

**Текущий расчёт:** проект декомпозирован на **22 работы**, модель ресурсов — **4 FTE**, суммарная трудоёмкость — **1584 чел.-ч**. Лучшее расписание занимает **89 рабочих дней**, при старте 23.11.2026 расчётное окончание — **25.03.2027**.
