## Кратко по фазам

### 1️⃣ Фаза 1 — Выбор концепции
Подготовить минимум 4 концепции и 4 критерия, провести трёхточечное экспертное оценивание, применить нечёткий коллективный TOPSIS и чёткий коллективный МАИ, затем выбрать итоговый вариант.

### 2️⃣ Фаза 2 — Распределение работы
Декомпозировать работы фазы 3, оценить трудоёмкость и предпочтения участников, сформулировать задачу распределения и найти оптимальное решение.

### 3️⃣ Фаза 3 — Оценка проекта
Подготовить не менее 10 Use Cases и оценить проект через COSMIC Function Points, Use Case Points и коллективную экспертную оценку.

### 4️⃣ Фаза 4 — Прогнозирование
Разбить фазу 5 на задачи, дать им трёхточечные оценки и спрогнозировать срок выполнения двумя моделями Монте-Карло с 80% достоверностью.

### 5️⃣ Фаза 5 — Планирование
Разбить реализацию проекта примерно на 20–25 задач, определить ресурсы и зависимости, сравнить эвристики планирования и построить календарный план для 8-часового рабочего дня и 40-часовой недели.

## ✅ Правила ведения работы

Основной таск-трекер — [GitHub Issues](../../issues).

Для каждой задачи фиксируются:
- исполнитель;
- период выполнения;
- планируемое чистое время;
- фактическое чистое время;
- результат или ссылка на артефакт.

В Issues также заносятся митинги, дополнительное изучение материалов и другая фактическая работа по предмету.

Распределение ответственности дополнительно отражается в [матрице RACI](RACI.md).
