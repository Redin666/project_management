## 1️⃣ Фаза 1 — Выбор концепции проекта

### Суть фазы

На первом этапе команда должна выбрать концепцию небольшого программного проекта, с которой будет работать дальше на протяжении остальных фаз.

Для этого необходимо:

- придумать не менее **4 концепций программного проекта**;
- сформулировать не менее **4 критериев оценки**;
- каждому участнику дать экспертные оценки важности критериев и альтернатив;
- упорядочить три оценки как **пессимистичную, ожидаемую и оптимистичную**;
- определить лучший вариант методом **нечёткого коллективного TOPSIS**;
- определить лучший вариант методом **чёткого коллективного МАИ**;
- сравнить полученные результаты и сформулировать итоговый вывод.

➡️ [Материалы Фазы 1](phases/phase-01-concept-selection/README.md)

**Результат Фазы 1:** выбрана концепция **A1 — «Система управления результатами тестирования на проникновение»**. Она используется как основа Фаз 2–5.

➡️ [Организация Фазы 2](phases/phase-02-work-distribution/README.md)

## 2️⃣ Фаза 2 — Распределение работы

### Суть фазы

На втором этапе команда должна распределить между участниками работы следующей фазы на основе **трудоёмкости задач** и **индивидуальных предпочтений**.

Для этого необходимо:

- сначала разбить работу **Фазы 3** на отдельные задачи;
- оценить сложность или трудозатраты задач **экспертным путём**;
- каждому участнику дать **индивидуальные оценки предпочтительности** задач;
- сформулировать и обосновать задачу распределения на основе трудоёмкости и предпочтений:
  - определить переменные решения;
  - задать целевую функцию;
  - определить ограничения;
  - задать правила балансировки нагрузки;
- решить задачу распределения с использованием подходящего инструмента, например **Pyomo, OpenSolver, NEOS** или другого оптимизационного средства;
- зафиксировать итоговое распределение работ Фазы 3 между участниками.

➡️ [Материалы Фазы 2](phases/phase-02-work-distribution/README.md)

**Результат Фазы 2:** выполнены декомпозиция Фазы 3, экспертная оценка трудоёмкости и индивидуальные предпочтения; сформулирована MILP-задача распределения и решена в **Pyomo + HiGHS**. Оптимальное распределение подтвердило текущих исполнителей, поэтому переназначение задач не потребовалось.

## 3️⃣ Фаза 3 — Оценка проекта

### Суть фазы

На третьем этапе команда должна оценить масштаб выбранного проекта несколькими независимыми способами и на основе результатов определить примерную трудоёмкость, состав команды, срок реализации и возможное сокращение функциональности.

Для этого необходимо:

- подготовить не менее **10 Use Cases** выбранного проекта;
- для Use Cases учитывать не только основной, но также **альтернативные и негативные сценарии**;
- оценить функциональный размер проекта методом **COSMIC Function Points**;
- оценить проект методом **Use Case Points (UCP)** и получить ориентировочную трудоёмкость;
- коллективно оценить трудоёмкость Use Cases, User Stories или более мелких элементов проекта экспертным методом;
- добиться согласованной коллективной оценки и агрегировать её в оценку всего проекта;
- сопоставить результаты **COSMIC, UCP и экспертной оценки**;
- определить:
  - примерный размер команды;
  - необходимые роли и специальные компетенции;
  - ориентировочный срок реализации;
- определить менее важные, но ресурсоёмкие функции, которые можно исключить или перенести за пределы MVP;
- сформулировать итоговый вывод о масштабе проекта.

➡️ [Материалы Фазы 3](phases/phase-03-project-estimation/README.md)

**Текущий результат Фазы 3:** подготовлено **12 Use Cases**, выполнена оценка **53 CFP по COSMIC** и **100,901 UCP** (ориентировочно **2018 чел.-ч** при 20 ч/UCP), коллективная экспертная оценка составляет **68 чел.-ч**. Следующие задачи сопоставляют методы и уточняют трудоёмкость.
